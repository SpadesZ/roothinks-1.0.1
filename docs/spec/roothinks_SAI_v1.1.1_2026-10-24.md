# Roothinks SAI v1.1.1 修訂條款

日期：2026-10-24。承接凍結的 [v1.1.0](roothinks_SAI_v1.1.0_2026-10-23.md)，以本條款修正研究者自主、協作及恢復契約；原規格與 PDF 不覆寫。文件版號不代表全面產品、科學或正式環境驗收。

## 三種同等受支援的研究流程

| 流程 | 最小路徑 | 禁止的隱含前提 |
|---|---|---|
| 獨立研究 | 建研究 → 文獻／筆記／作者決策 → 寫作 → 保存及修訂 → 匯出 | 不要求教授帳號、MentorLink、PI 署名或審閱核准 |
| 選用教授指導 | 獨立研究 → 邀請並接受 → 版本意見及資源 → 作者回覆 → 原教授確認或要求再修 | 未解意見、撤銷邀請、教授退出或移除，不阻擋作者繼續研究與匯出 |
| 團隊協作 | 專案擁有者明確邀請 → 接受指定權限 → 指派章節內讀寫 → 退出／移除 | 署名、學術身分不授權；限定共同作者不得讀全文、其他章節、整個文獻庫或匯出全文 |

所有流程保留既有研究、來源及歷史。舊資料缺版本或來源關係時顯示未追蹤，不自行補成「已確認」。獨立研究者可以自行作學術決定；系統不得以教授來替代研究者的主體性。

## P0-AUT：學術身分與權限分離

- `AcademicProfile` 是自行申報的背景，非機構驗證；系統角色、WorkspaceMember 專案權限及署名分開。
- PI／Co-PI、姓名與 `access_role` 署名資料不授權。啟動不得從署名恢復已撤銷的權限。現有正式 membership 不自動移除或升權。
- 教授透過一般註冊及學術背景頁加入。教授邀請只給全專案 viewer／審閱權，不給 editor 或系統管理權。
- 專案 owner 建立綁 Email、七天期限的一次性邀請。只向 owner 顯示一次原碼，DB 保存雜湊；owner 核對身分並以可信管道交付，系統不自動寄信。
- 受邀者以對應 Email 登入，核對專案、範圍並出示邀請碼後才授權。拒絕冒領、錯碼、重用、過期、被撤銷與已失 owner 權限者的邀請。
- 邀請不覆蓋其他既有授權；coauthor 必須列指定章節。新增授權、接受、拒絕、撤銷及理由留下歷史。
- owner 可撤銷或移除，受邀者可退出。最後一位 owner 必須先明確移交管理權。
- 移除只撤銷當下存取與章節指派，不刪作者成果、原教授意見、附件、回覆、決策或版本。作者仍可查看歷史，畫面明示原審閱者已無存取權。
- 教授只看雙方當下共享的專案；不得藉研究者關係看到其他專案名稱、筆記或全帳號登入活動。admin 不替代 project ACL。

驗收 A01：無教授帳號建研究、保存兩版並匯出真正 DOCX。A02：教授註冊但未接受前無專案權限；接受後審閱，作者回覆，原教授處理。A03：撤權後教授 API 拒絕，作者能讀原意見並繼續保存／匯出。A04：團隊只寫指定章節，其他章節與全文匯出拒絕；退出後拒絕且歷史保留。A05：CSRF、惡意 JSON、角色偽填、錯碼、重用、過期及最後 owner 控制。

## COC-05：變更影響及追加重核

- 已確認的作者決策保存段落、目的、主張、條件、禁止延伸、來源定位、採用理由與指紋。原 PDF 有登記時驗原件雜湊；無原件時不得稱已核對原 PDF。
- 來源／原件／採用理由／原章節改變或確認被接續時，標出受影響證據、主張、全文版本及原審閱。新稿記錄決策依賴；舊稿只可推定可能依賴並標明推定。
- 作者重新確認必須明確勾選、填理由、綁當前快照與實際保存的最新章節。矛盾、缺證據、過時快照、錯版本、漏原依賴須拒絕；保留表單輸入。
- 新確認以 `supersedes` 接續，原確認不改寫。舊確認不能繼續交給生成使用。並發接續同一確認只有一個成功。
- 限定共同作者只可使用本章明確交付的證據；完整作者重新交付新快照後可使用新授權。舊指紋不授權新來源，猜 ID 不能取得其他來源。
- 作者確認、稿件重核與原教授重核是三個不同動作。後兩者須覆蓋原依賴、同版本實際段落及目前有效確認；其他人不能代替原教授重核。
- 原審閱狀態、後來的依賴失效與重新確認分開。未追蹤章節持續顯示，不標全面科學通過。普通寫作／保存／匯出維持可用。

驗收 C01：來源改動沿依賴圖失效；原件竄改亦失效。C02：未解矛盾及過時快照拒絕、輸入保留。C03：作者、稿件、原教授分別追加確認且舊歷史逐字不變。C04：再次來源修正再失效，未追蹤範圍仍明示。C05：跨專案／章節、未交付證據、偽填 actor 與錯版本拒絕。

## REL-05：受控停機的一致研究備份

本輪支援單機、本地檔案系統、資料根目錄內 SQLite 的完整停機快照。所有 app／worker 必須完整停機，或配合本版 runtime lease。這不是線上 HA 備份；不支援外部 DB、多主機或任意不配合鎖的 writer。

- 來源與目的地互不包含；備份與還原只建立全新目錄，不覆寫、合併、刪除既有研究。
- 啟動在 schema 寫入前取得 app 生命週期 lease。活動 app 阻擋備份，備份 gate 阻擋新 app；程序死亡後 OS 釋鎖。
- 涵蓋資料根目錄的原 PDF、研究檔、筆記、決策、草稿、稿件、圖像、審閱資源及 SQLite。SQLite 透過標準 backup API 納入已提交 WAL，來源 journal 模式不改。
- manifest 含檔案大小／SHA-256、目錄、DB schema 指紋、逐表筆數／內容指紋、integrity_check 及 foreign_key_check。外部 DB 配置不可宣稱完整快照。
- 拒絕連結／junction、路徑逃逸、大小寫碰撞、未知 sidecar、秘密設定檔與缺完整 marker 的成果。備份含私密研究資料，永不提交 Git。
- 故障／中斷保留原資料與部分成果，但不能發布成功。還原 pending marker 阻止 app 在未完成目錄補建空 DB；完整性全部通過後才發布完成 marker。
- manifest 雜湊只證明內容一致性，不證明備份來源真偽；未提供簽章、加密、異地保存或正式維運排程。

驗收 R01：原件、決策、修訂及審閱歷史還原，仍維持教授撤權且啟動不補權。R02：活動程序／備份互斥、硬退出後解鎖。R03：複製、WAL、manifest、DB 或還原故障均不可假成功。R04：不完整還原不能啟動補空 DB。R05：Windows 與隔離 Linux 執行相關程序及完整性檢查。全站健康、容量門檻、多主機及斷電另列未驗。

## SCI-BASE：可重現的科學驗證起點

依 [固定合成基準](../engineering/SCIENTIFIC_BENCHMARK_PROTOCOL.md) 保存案例、人工答案、評分器、程式 SHA 及觀測。量測來源定位、條件保存、來源條件覆蓋與未支持控制敘述；人工答案不進 provider prompt。缺證據與錯誤不可剔除。

來源可定位、作者已確認與條件字串完整，不代表主張有科學支持。受控替身可能保留未支持敘述，必須如實列出。真模型品質、真文獻盲測、可用性、作者聲音與 AI 偵測分數不在本輪成績中推定。
