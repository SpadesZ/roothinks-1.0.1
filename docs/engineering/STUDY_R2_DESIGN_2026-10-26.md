## 1. R2-A 審閱存取範圍

**P1 發現**：教授邀請的語意是「只授予審閱權」（`collaboration.py` 明文），但 Study 與導師 API 讓教授讀到研究者的私人草稿、對話與所有筆記。

規則：
- **審閱身分** ＝ 該專案角色為 `viewer` **且**有一筆已接受、未撤銷的 `ProjectInvitation(kind='professor')`。
  以邀請紀錄判斷，不新增資料表欄位；撤銷時既有流程會刪成員資格並把邀請標 `revoked`，因此自動失效。
- 一般團隊 viewer、舊的 MentorLink 關係（沒有教授邀請）、被 owner 改成 editor 的教授：**行為不變**（相容性；是否收緊交 Owner 決定）。
- 審閱身分在 Study 只允許：頁面、`check_gate`、`paper_list`、`get_fulltext`、`media_*`（論文本身，不是研究者草稿），以及
  `evidence_notes` 清單與匯出——**只含已請求審閱的筆記**。其他 Study API（自由筆記、對話、矩陣）回 403。
- 導師 API `mentees/<id>`：對審閱身分的專案不回傳自由筆記與對話，改標 `withheld: review_scope`。
- 前端：Study 頁面在審閱身分下不呼叫被禁止的 API，顯示「審閱模式」說明。

## 2. R2-B 證據語意

- **兩種主張分開**：`text_match`（引文是否真的在原文出現）與 `claim_support`（引文是否支持該陳述）。
  系統只檢查前者；後者只有研究者能標註（`not_assessed`／`supports`／`partial`／`does_not_support`，記錄誰標的），預設 `not_assessed`。
- 不再使用 `verified`：錨點狀態常數改名 `TEXT_MATCHED`；筆記層 `evidence_status` 改為 `quote_match: found|none`；
  論點標籤「有原文引文」改為「附原文引文（未判定是否支持）」。舊資料讀取時轉換，不改寫檔案。
- 正規化改嚴格：只收斂空白、彎引號、破折號、軟連字號、不換行空白與 `ﬁ ﬂ` 連字；**不使用 NFKC**（避免 `10²`→`102`、`H₂O`→`H2O`）。
- 字界檢查：引文首尾若是英數字，原文對應位置的外側不得緊接英數字。
- 太短的模型引文（少於 3 個詞且少於 20 字元）不可作為證據，列為「太短，無法歸屬」。
- 同段多處：前後文能唯一決定才給位置；前端另送 `occurrence`（第幾處）作為唯一決定的依據；仍無法決定時狀態 `ambiguous_in_block`，**不給 start／end**，畫面只標整段。
- 譯文推定：由譯文選段推定的整段原文標 `match_kind: paragraph_from_translation`，畫面標「由譯文推定的整段原文，非逐句對應」。

## 3. R2-C 筆記所有權

- 證據筆記的陳述**只有作者**（`accepted_by`）能直接改寫或刪除；作者不明（未登入的開發模式）時維持舊行為。
- 其他成員改用「建議」：`suggestions` 只追加，含提議的陳述、理由、提議者；作者可「接受」（套用並記錄是哪一則建議、誰提的）或「不採用」（附理由）。
- 請求／撤回審閱只限作者。
- 留言維持只追加。專案共用的自由筆記不變（既有功能，另列為 Owner 決定事項）。
